# 持续迁移目标与变更校验规则

持续目标为完成 py-elk 剩余 E09–E21 原生Python迁移与独立包交付。E10–E12先交基础包，后续补齐全量能力；py-mermaid集成继续作为独立后置步骤。实际进度以 iteration-plan.json 为准，不把基础包当作全部ELK迁移完成。

每批先列变更及依赖，再选对应模块、API、协议和必要负控制。已有成功检查在依赖未变时保留，不因轮次结束重复运行；纯校验器变化优先重核原始数据，不自动重采全部布局。对需要新实际计算的算法/输入/包变化，只运行受影响案例和必要代表性回归。未识别影响时先补依赖分析，不自动触发全量。

来源核验、许可证、真实安装包身份、原始字节、失败保存及独立复审要求继续适用。改进验证协议不能倒改旧执行源码SHA、伪造新执行或缓存PASS。所有结果明确记录检查范围、未检查范围及 fullValidation=false；历史全量结果只证明其当时版本。

全部计划功能完成后，再执行一次完整功能/算法/选项/平台与打包验收。此前不逐轮启动 scripts/check.py 的full模式或三平台全套。必要的平台专项、发行安装/下载校验按其实际变更和交付目标执行。

现有 scripts/check.py --affected 对未知路径仍可能回退full，所以持续goal期间不盲用该回退。先执行明确选择的命令，再用变更收据工具核对真实命令、日志和计数：

```shell
python scripts/iteration/check_changes.py --manifest docs/iterations/E09-validation.json --baseline test-runs/20261103-E09-01/starting-snapshot.json --out test-runs/E09-change-check-01.json
```

该工具自身记录SHA，不属于旧布局采集器的执行依赖；它不会启动测试或全量检查。manifest是本批已选检查的明确清单，不声称自动证明所有影响均已覆盖。新的实际检查先执行再记入清单，不能只改摘要。
