# Math.random 的原生宿主边界

Spore importer在重复中心上执行固定源67352–67364的while：先查完整中心key，碰撞时依次读取X、Y两次`Math.random()`，各加`(r - 0.5) * 0.001`，两坐标更新完才再次查表。该路径不读取ELK的`randomSeed`，也没有迭代或图数量上限。固定worker、完整caller和常量字节见E19的jitter源闭包及独立review。

原生`Session.random_unit()`为这个宿主调用点提供`[0,1)`值。当前实现读取操作系统8字节熵，取高53位，除以`2**53`得到可精确表示的binary64值。它不创建与布局seed关联的发生器，不占用JavaRandom流，不读取fixture、节点ID或预存几何。操作系统熵读取失败直接传播，不以固定值代替。

这是原生宿主随机边界。V8与CPython的内部随机状态和具体轨迹不作为相等承诺；同一无seed输入重复运行本来就没有唯一几何金样本。重复中心仍按实际源循环和更新顺序处理，不忽略jitter、不改成确定性小位移，也不限制碰撞图域。

校验分开保存：真正宿主抽样只核有限值与半开区间；在独立控制中替换原Math.random和原生随机getter，核明确draw序列下的guard、调用次数、X/Y次序、增量和对象状态。控制模式必须标明instrumented，不宣称使用原V8随机轨迹，也不作为生产fixture分支。无碰撞或显式确定性分支继续严格几何对照；有真实随机扰动时保留原strict差异，另核源允许的随机性质和几何不变量，不以放宽全局容差掩盖它们。

本决定只处理Math.random宿主调用点，不更改ELK的种子算法、既定identity策略、有限输入规则、公开注册或正式发行状态。
