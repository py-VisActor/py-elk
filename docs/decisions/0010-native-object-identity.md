# 原生对象 identity 与桶顺序

通用宿主的内部 `session.identity_hash(object)` 返回 signed32 code。当前原生实现按进程递增分配首次请求的 code，在会话内保存对象引用与 code，避免 Python 地址复用；同一个对象在该会话中保持同一个 code。计数按低32位转换，集合必须处理实际碰撞，不增加图规模上限。

radial R07/R09 使用源中的桶首插顺序，再在同一 hash 桶内按对象 identity 去重。两个原 Node 观察说明已有 hash 的数值逆序不改变桶首插序；额外 instrumented 控制制造32位碰撞，展示整体插入0/1/2会遍历为0/2/1。因此不能把所有情况都改成一个全局 insertion-order list，也不能将 E09 新鲜 LEdge 的专用证明推广到该域。

原生 code 的分配点来自原生对象与集合请求。GWT 的完整运行时还会为其它对象分配 `$H`；其进程级分配轨迹未被复制，两个进程的 code 值不作为相等承诺。原始 strict 输出差异继续保存，已知 geometry 对照与宿主身份策略分开验收。发生 hash 碰撞时算法仍按其得到的真实 signed32 code 执行桶语义；正常原控、人工改写原对象 hash 的控制分别标明。

用户 JSON 中的 `$H` 作为原业务字段保留。它不会被解释成原生内部对象的 hash，也不会驱动布局中的身份分配。内部 getter 可用于独立集合 primitive 控制，运行时代码不得读取 fixture ID、预存输出或特例 hash 表来获得预期几何。

该决定只处理内部宿主身份与集合语义，不代表完整 radial、公共算法注册或发行验收完成。项目自身发布许可仍由单独的许可决定记录落实。
