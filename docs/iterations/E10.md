## 固定输入与退出条件

使用 E09 的同一基础 profile、真实原生代码及40组件诊断来源闭包，保留完整12/243/8及25 master 分母。0–8原始节点/最多28边是当前受审输入域；benchmark 中的小/中/大只表示该域内相对规模，不拿超过边界的拒绝请求冒充大图性能。扩大节点/边/数值域须先续审源组件和依赖，不能在性能轮取消 guard。

CPython 3.11–3.14、Windows/Linux 逐项记录实际解释器、系统、机器、wheel/sdist SHA、隔离安装、仓库外 -I/空 PATH 的真实布局、诊断、错误和生命周期。没有安装或不能实际执行的格子标记未测，不用一个版本代替整张矩阵。上游 Node 仅开发期对照，不进入 Python 产品运行。

性能保存硬件/负载、输入及 seed、样本量、每次原始观测、clock含义、耗时分布和峰值内存采集方法。ELK 返回的 executionTime 保留固定生成源标尺；benchmark 外层时钟另记正常 elapsed seconds，不混用。先测量再确定可声明的性能和资源边界，不编造 CPU/内存硬配额。

## 应用 E09 的具体改进

1. **先排重、再冻结包。** 搜索中英 README/API/示例中的旧范围和时间单位，做一次文档口径清单；METADATA 会包含 README，不能在构建后才改陈旧段落而继续复用旧wheel。
2. **真实 caller 边界先审。** 把导入、算法、回填、JSON外层与进程启动分别标注；检查器的 wall seconds、进程 CPU seconds 与源诊断标尺分开。不用树形正确代替采样位置正确。
3. **首个小交付带动并行。** schema、collector、纯校验器和一个实际异root正本先交给反审者，随后再扩展矩阵、生成案例与负控制，减少最后串行反审。
4. **基线不占当前写面。** 基线在不可变完整副本执行，当前准备/实现可并行；仍检查基线副本执行前后SHA，不以并行本身宣称加速比例。
5. **保持原始证据角色。** source facts、静态声明、实际同wheel运行和后验结论分别保存；只重采受代码/输入变更影响的真实事实，纯校验每次重算且不缓存PASS。
6. **保留语义迁移。** 原测试方法改名或历史拒绝分支变为已实现时，记录旧断言到新正/负断言的迁移，不虚报原方法名集合完全没变。
7. **按实测设置 deadline。** 已超过90秒的完整 conformance 组不能套用90秒命令上限；先读基线成本，再为新增案例留出合理预算。超时保留原日志，只核查和回收自己创建的明确PID，不扫杀其他 Python 进程。
8. **先验证进程身份规则。** Windows venv 可存在 launcher 中间进程，Popen.pid 与引擎 os.getpid 不必相等。先用真实 -I 小正本核 observed parent/launcher 关系，再冻结拒绝重复执行证据的规则；不要把合理的宿主差异当伪造。
9. **包清单在采集前核对。** 仓库包目录还含未打包说明文档，实际wheel分母按 py、许可和 py.typed 清单核算。先以真实安装身份核 package/METADATA/绝对且非源码路径，再跑全套；缺运行文件、缺许可、多文件、字节变化和重绑源码路径都应有语义负控制。
10. **评估拆分采集与纯验证代码。** E09 沿用严格的全部源码context，单纯校验器修复也须重新实际采集。E10 可单独设计新协议：把不变的采集入口及其完整传递依赖、请求/策略/包/解释器/环境绑定为执行身份，把当前纯校验器SHA另存并每次重算原始观察。旧收据及原sourceSHA不重写；必须先用遗漏依赖/换采集器/换环境/错原始字节负控制证明不会复用受影响执行，再实测是否减少重采成本。该方案尚未实施，不计作本轮已提速。

先完成各真实矩阵及资源/性能事实，再绑定当前源码/包/README/METADATA、独审 accepted/blockers/filesSha256 与便携收据；所列平台/性能/资源专项通过后更新相应门禁。本轮只执行与平台、性能、资源变更有关的专项检查；全部迁移功能完成后再执行最终full。记录每个平台跳过及理由，正式发行和集成状态不提前提升。
