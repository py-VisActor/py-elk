# 18 批执行 brief

从机器计划指向的 17 批 checkpoint 恢复；先运行其纯绑定脚本，读取限定 code receipt 和尚未完成的 draft 清单。不得把 private 完整 compound、DOWN 或 prepared Spline 的通过状态提升为全部 Layered、公开包或完整算法验收。

| owner | 单写范围 | 优先交付 |
| --- | --- | --- |
| A | provider/factories、方向和高级 label processors | 保留已审 DOWN/compound；按真实 Spline 工厂接新的 JSON caller，原版故障与正本分开；完善 Inserter/Remover、六策略 Switcher、SideSelector，接一个真实 label 完整调用 |
| B | Polyline/Spline 路由与新 prepared 对象 | 保持已审 Spline/Final 稳定；PL driver 和数学闭包分别源批后落实完整 Polyline，单次新原版与首候选，随后交 A 接工厂完整 caller |
| Root | 共享依赖、剩余 Layered 策略清单、独立源/代码审与归档 | 优先解除真实 caller 阻点；划清其它 cycle/layering/crossing/placement 备选策略缺口；按一个可调用策略交付，分担 A/B 独审 |
| V | 独立源审、代码审和首个新对象 | 按实际消费者依赖排序，避免重复 Root 已接范围；保留完整原始报告和首负控制，优先审新 body 与新调用者 |

并行规范不变：共享文件单 owner，接口先定，源批先于数学实现，代码独审后接调用者。仅草稿的函数不能用 no-op、bbox 或空集合交付成功；新 helper 应尽快出现真实调用而不是等待整组工具完工。各 owner 的源码/报告/冻结版本须有精确 SHA，不借用当前 checkpoint 认证旧运行。

校验见 [17 批入口](NATIVE_COMPOUND_COMPACTION_SPLINE_VALIDATION.md)。旧默认、自环、平台和已通过 prepared 组不作每批启动检查。保留 raw 哈希/身份顺序差异与真实上游失败；完整功能完成后再全量。本批结束按交付、并行分工、问题改进和下一批复盘，不自行提交、推送或发布。
