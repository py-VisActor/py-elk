# 17 批执行 brief

承接 16 批新增的层级、Spline、凸包及南北轴证据。以机器计划的最新 checkpoint 和各范围 code receipt 为准；旧默认 19 阶段、自环 23 阶段不作启动回归。

| owner | 单写范围 | 首要交付 |
| --- | --- | --- |
| A | hierarchy/import/provider/factories 与剩余 hierarchy handlers | 用真实南北轴接 hierarchy 正交处理，完成 constraints/size/position 等必需消费者后运行一个新的完整 compound 原版与候选；随后真实方向和高级 labels |
| B | spline_general / spline_final | 保留已批 foundation/ranking，完成真实 producer/driver 与 Final CP；每个输入只采一次原版，新 caller 用冻结代码校验 |
| Root | orthogonal_axes、rectilinear_hull、component_compaction / connected_compactor、共享容器与归档 | 先消除阻塞实际 compound 的共享缺口，再按 CT/CC 源审实现完整压缩；Pair helper 由 Root 单写，复用同一真实 allocator |
| V | 独立源审/代码审查/新增原版控制 | 优先解除实际 consumer 的阻点；Root 分担源审与 prepared 对象控制；避免所有小叶子堆到一个 reviewer |

先完成单个新调用的真实结果再扩范围。容器 value hash、默认值 owner、异常前后的副作用和调用顺序作为实现审查的一部分；不以 bbox、空集合、假默认或 no-op 补未实现数学。未执行的草稿单列，不以 checkpoint 文件数声明完成。

复用 16 批[校验手册](HIERARCHY_SPLINE_COMPACTION_VALIDATION.md)，新输出目录、实际执行脚本、源码 SHA 和首失败必须保留。原样保存历史证据；观察器错误优先从保存数据复核，确需新执行只跑受影响对象。全部功能完成后再全量；本批不自行提交、推送或发布。
