## 并行执行

root负责preflight、affected、完整入口、metadata收尾、计时与全局记录；A独占审计夹具与依赖复制；B独占单次来源数据缓存与接入；V独占同批请求计划及收据复验。稳定接口先交付，其他工作继续，交接以文件SHA和实际日志为准。

A独审root工具与B缓存，V独审缓存和夹具，B独审请求执行身份。计时阶段停止其他重负载，按基线→优化版、独立请求→共享请求顺序执行；计时完成后才并行运行WSL和Git副本。这轮没有串行人员开发对照，因此不宣称sub-agent使开发速度提高多少。

## 问题与改进

| 实际问题 | 修复与保留的证据 | 后续规则 |
| --- | --- | --- |
| 稀疏夹具初次漏掉依赖文件，会把缺文件误当目标拒绝 | 先运行完整正副本，再做单项变异；保留首败并补齐真实读取闭包 | 新依赖必须纳入复制清单并通过正控 |
| JSON序列化相同的list→tuple或str键→int键污染可逃过普通摘要比较 | 增加严格类型、键、有限值、循环及scope退出检查；独立负控确认拒绝 | 只复用本次只读数据，不复用PASS；独立调用重读字节 |
| affected路径规则会误忽略夹具中的build/dist目录或许可证Markdown | 顶层产物排除与真实输入分开，未知影响退回完整检查 | 来源、许可、ADR和公共模型修改要覆盖真实依赖 |
| 命令名称、日志自洽仍可能把局部发现范围伪装成full | 收尾器独立核对29/45条准确argv、cwd、scope、环境及原始计划字节 | 不靠摘要布尔值认证完整检查 |
| 后续进程只读复验误将调用者临时环境与原执行环境比较 | 执行身份继续绑定真实完整环境；只读复验检查已记录的执行证明及隔离策略 | 提前安排跨新进程验收，工具修复后重新计时，旧记录不重绑 |
| 增加守卫后版本变化，第一次754项测量不能冒称最终758项 | 初测与最终测量分别保留，最终只接受冻结屏障对应版本 | 性能报告必须绑定实际工具/测试SHA |
