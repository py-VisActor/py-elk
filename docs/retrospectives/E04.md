# E04 复盘：首条真实原生ELK执行链

E04从E03宿主模型出发，接通受限但真实的Python `ELK`：空图源内leaf支路、非空图默认19调用、13个intermediate、六次phase调用及生成实现的随机流，最后真实导出ELK JSON。
输入限0–4节点的flat连通单向无环简单路径、RIGHT/缺省、ORTHOGONAL，具体数值/选项/已有字段边界见[ADR0003 revision4](../decisions/0003-e04-generated-source-slice.md)与[使用手册](../E04_NATIVE_SLICE.md)。不支持的拓扑和配置明确失败。

## 交付与验收

root先保存原始373文件，跑276项离线基线。A/B/V按独占文件并行调查与实现，source批准后才移植相应组件。
实际源为固定elkjs0.12.1生成worker，原源SHA、传递helper、host数值/collection映射、分支条件、有效写操作和许可逐组件绑定；source gate只对本支持域verified，精确外部Java build及项目自身正式发行许可仍未解决。
最小async API保持输入/构造参数/调用参数不变，每call独立工作图/RNG。计算仍在调用线程，terminateWorker仅为本地幂等关闭，不宣称完整调度/取消/生命周期通过。

V锁定21个实际输入：5个master原字节与16个新增变体；原25分母保留、20个排除原因可查。A另外封存12个真实官方数值正例和1个有效padding Mapping的参考失败，包含小数、零尺寸、subnormal、近1e6与错序。
本地build03生成wheel/sdist，安装到新venv；候选以-I、空PATH、无PYTHONPATH/PYTHONHOME实际执行。wheel name/version/METADATA/导入位置、全部package字节和当前src/许可字节一致，21例每端各3次通过公开合同exact、独立geometry和exact重复确定性。
真实wheel SHA `7ebf9e042028bb4fdc3e73270066d398c285a1af2c5b2cb3cc7a39c5e30d95f7`；[安装历史收据](../../references/e04-installed-check.json)和[runtime审计](../../references/e04-runtime-audit.json)版本化保存。最终完整测试数量、平台与源码指纹见[本轮记录](../changes/20261103-E04.json)。离线审计不冒称重新执行历史wheel。

## 并行执行

A负责内部LGraph、有序双向邻接、导入/导出及13中间处理器；B负责GREEDY、NETWORK_SIMPLEX、两次LayerSweep、BK、ORTHO和真实RNG；V独立锁suite/oracle、source绑定与反例；root负责scope/真实调度/API、安装检查器、共同比较逻辑、全局状态与文档。
来源调查、suite准备和纯host图表达先并行；root冻结接口并逐组件审批后，已获批组件先实现，其余继续调查。全局source gate等整个slice闭合；运行验证另判，不把部分审批当完整算法通过。
A审B、B审V、V审A/root。A/B真实阶段状态与官方插桩对照，V独立检出入口/安装/声明问题；所有修复回owner。root在各owner稳定后统一集成，后补历史审计仅由明确owner写两文件，最后再次冻结检查。
没有串行对照计时，不报告加速倍数。实际收益是源码闭合、实现和独立oracle准备可以重叠；公共图协议和真实导出仍需按依赖串行集成。
