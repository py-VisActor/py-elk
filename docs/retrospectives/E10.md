# E10 复盘

## 交付与验收

复用 E09 同一开发 wheel/sdist，产品运行文件和 METADATA 未改。Windows/Linux × CPython 3.11–3.14 共八个 wheel 格实际安装/运行通过；Windows 3.13.15 与 Linux 3.14.10 各一个 sdist 代表格通过，其余 sdist 小版本格未测。每格六请求、元数据/关闭错误、真实 running 取消/回收/恢复均保存原始数据。

三档 bounded 输入各一次预热、五次正式 public 样本，共18次；Linux CPython3.14.10 的中位调用耗时约76/83/236ms。父/子 CPU 和各自峰值 RSS 单独报告，峰值不相加。另有三次独立插桩、每次25个实际区间，输出/trace与公共样本一致；插桩成本不加入公共吞吐统计。结果仅代表当前机器和0–8节点/最多28边域，不是 Windows 性能、硬资源配额或无界图能力。

本轮14项针对性测试通过；六份交叉独审接受，纯重算入口验证八格 wheel、两份 sdist、18次 public 与三次 instrument。未运行全项目全量、旧181/144矩阵或三平台 full。完整算法仍0，12/243/8及25 master分母不减。

## 并行执行

A负责Windows和公共collector，B负责Linux/性能，V负责纯比较器，root负责协议、固定输入、归档、公共性能重算与集成。平台格可并行，性能在平台重负载完成后顺序执行。首次真实单格带动比较器，采集执行依赖与纯核验代码分开；之后比较器修复均重核原 raw，没有再次采集全部布局。

## 问题与改进

collector的采前/采后十依赖稳定检查冻结较晚，Linux前一批在源码变化中执行，原始数据保留且未重绑SHA；只重采受影响四格，约5.8秒。下一轮应先冻结共享采集器，再明确向所有执行 lane 广播 SHA 后放行。纯核验发现两种跨字段不一致：改 versionInfo 却保留原 sys.version，以及改 OS 却保留 Windows 路径/PID方法；在原四类负控内补核并复验，不扩成大规模对抗审计。

首次Linux下载目录误选无权的 /root cache，修为已盘点的实际用户目录；未改系统解释器。首次benchmark父启动器使用 -I 导致可信工具同目录导入失败，第二次只让父启动器使用 -B，所有真实候选子进程仍保持 -I/空PATH。root最初复用比较器时缺观察 envelope/engine，修纯适配视图后通过；没有伪造 wall clock，也没有更改原 raw。

公共性能采集器先冻结，额外插桩另文件，避免工具细化使18个已完成样本失效。Linux sdist 的真实两步构建/安装链与 Windows 直接安装分别核对；不强行要求两个系统采用同一命令形状。上述首次失败、原输出和旧检查报告均保留在本轮 test-runs。

收口时一份测试自定义日志缺少超时/完成区间字段，标准变更收据拒绝；只补跑受影响的三个collector协议方法生成标准记录，没有重采平台。下一轮统一使用现成命令记录器，复盘也沿用规定的四个段落标题，避免重复修正收口格式。
