# 共享 JSON 宿主与树形阶段复盘

本批实现通用 JSON 持久状态、原对象/当前容器分离、section 关系与条件传回。四个既有官方坐标请求通过几何/业务对照；新增 detached 根自环原请求发现并修复了全 edge 列表遍历与源 containment 遍历的差异。完整 strict 的对象 `$H` 差异原样保留，未用生成编号伪造运行时相同。

校验严格跟随实际变更：JSON 初稿四个方法、enum parser 调整后一个方法、detached 修复后一个方法；原四个成功官方请求没有随最后修复重复运行，也没有改其源绑定。新端口 runner 首次执行23项已有 primitive 对照，约0.124秒；这是新增脚本的必要检查，没有重采 Node、运行完整布局或平台矩阵。mrtree 独立对照为9个内部阶段对象与12个数值边界，不声称完整 provider 通过。

root 独占通用宿主和中央选项，A 保持 ports/NodeContext/size，B 保持 provider/tree/radial，V 独立对照。源码审查按角色可由 root 或 V 承担，保证与实现 owner 分离；本批 root 直接核 Walker 原闭包，V 并行完成 JSON 独审，减少单个审查角色的排队。已批准范围内 owner 直接实施，不逐函数重复询问。

实际问题有三项：原 JSON 与工作状态共用一个结构会误删旧字段；遍历所有注册 edge 会错误处理 detached 对象；Python `floor(x+0.5)` 在二进制半值附近会错误舍入。分别采用源要求的原对象映射、containment 范围和独立数值边界适配。GWT BigLong 仅作行为观察，未归入 ELK 许可或复制整套 runtime；后续源码仍需持续区分算法与其外部 helper 的归属。

本批没有建立新的整体提速百分比。局部比较耗时很低，主要剩余工作是完整算法与调用链移植。下一批 root 实现已审的20项 NodeContext typed options及真实默认覆盖；A 推进尺寸贡献，B 推进 routing/compaction/radial，V 按小块独审。全部功能完成后再全量，py-mermaid 集成仍独立后置。
