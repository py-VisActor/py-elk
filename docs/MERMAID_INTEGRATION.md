# 独立后续步骤：py-mermaid 集成

优先完成独立基础py-elk并在M5发布正式Python包。这里的I0–I3是后置独立步骤，**不属于基础包发布的前置条件**。
唯一行为基线是elkjs0.12.1；py-mermaid将布局后端替换成py-elk，不建立旧ELK版本/坐标兼容分支。
本轮不修改py-mermaid源码或默认配置。

| 步骤 | 交付与门禁 |
| --- | --- |
| I0 版本与能力 | 选择已发布py-elk版本，记录上层所需算法/选项/拓扑和缺口 |
| I1 适配 | 语义模型/已测尺寸/选项转换，几何回填与container变换，错误/取消/版本传播 |
| I2 分层回归 | 基础图/标签边/子图/方向/端口/配置/错误，随后复杂图；布局和绘图分别验证 |
| I3 集成交付 | 锁已发布依赖版本、完整支持范围和回归；按上层项目发布流程交付 |

基础0.1.0不承诺端口/标签/compound等高级能力。I0发现必需缺口时，等待M6/M7对应能力的新正式版本；
不能让这些集成需求反向阻塞基础包先发布，也不能在上层用JS/JVM fallback掩盖缺口。

| 职责 | 所属项目 |
| --- | --- |
| Mermaid grammar、语义、主题、CSS/HTML/Markdown、配置来源 | py-mermaid |
| 字体/标签测量、shape需求、Canvas绘制和图像导出 | py-mermaid / py-skia-canvas |
| ELK JSON、算法/选项、节点/端口/边/标签/层级几何 | py-elk |
| 语义→布局图→回填、选项映射、错误/取消/版本传播 | py-mermaid中的py-elk adapter；两端用共享契约检查 |

输入明确ID/层级顺序、已测尺寸、edges/sections、方向/间距/padding和选项；输出保留容器、坐标模式、几何/路由及诊断。
不能各做一次补偿布局，也不能把golden坐标/截图尺寸输入生产算法或按文字长度猜尺寸。

测试分为上层转换、py-elk对官方0.12.1布局差分、回填/坐标变换、Canvas视觉输出。
更新集成预期时记录engine/version/input/config/source SHA和原始几何；后端替换不等于旧oracle零差异，
也不通过放宽py-elk内部坐标标准来适配旧结果。
