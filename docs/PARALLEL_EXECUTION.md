## 1. 并行原则

在root已分配的私有源码范围内，V独立accepted且无blocker的小闭包可由owner直接封源并实现，无需逐函数再等待root二次批准；跨owner接口、公开能力声明、发行候选与共享文件写权仍由root统一协调。此预授权不允许将一个helper通过扩大为整条算法或整轮完成。来源批准后立即小步实现和实际对照，持续交付可恢复的源码检查点，避免只堆准备文档。

生产模块、来源事实及后验验收结果分别冻结；后续成功日志写run或最终记录，不为每个后验结果修改已审source文档造成反复SHA串审。已完成lane明确转交独占文档/测试任务后继续工作，原生产文件保持冻结。独立审查统一包含`accepted`、`blockers`和`filesSha256`，拒绝或覆盖缺失不可重绑摘要冒充批准。稳定模块立即集成，跨进程/异root真实小正本优先于大采集；只有代码或有效证据变化才重新执行已通过检查。

收据复用保存原始观察与命令字节并绑定实际角色、解释器和wheel；每个原用例仍独立重算比较/几何/确定性。重复执行数不能靠复制同一生命周期body伪造。完整差异视图可按内容摘要压缩，前提是原始观察仍可重算整个视图，不能缓存PASS。工具独审先真正常副本通过，再只修改目标语义并重绑相关摘要；初次falsePASS/falseFAIL保留，修复后用新run。

最多同时运行4个agent：根agent加3个sub-agent。子agent默认不再分派任务；根agent依据依赖、文件归属与实际空余槽位调度。
同一轮内部尽量并行，跨轮先满足明确依赖。只读调查、样例/断言准备和接口稳定的独立模块可以并行；存在数据/算法前置的阶段按依赖分波推进。
根agent保留一份整体任务清单和决定权。并行度以有效独立工作量为准，遇到强依赖先缩小任务或安排只读复核，不为占满槽位制造重复实现。
完成一个子任务不自动完成迭代；最终集成、全套验证和复盘必须经过根agent。

## 2. 固定职责与动态角色

| 角色 | 责任 | 不能独自决定的事项 |
| --- | --- | --- |
| 根agent：协调与集成 | 冻结本轮范围/接口、分配文件、处理冲突、汇总证据、运行集成检查、更新进度和复盘 | 不跳过来源/兼容/发行门禁，不用子agent口头结论代替证据 |
| A：主线实现/来源 | 本轮主要算法或来源链调查，交付可追溯实现/来源证据 | 不修改其他lane的文件、全局状态/版本/基线/兼容阈值 |
| B：互补实现/路径 | 与A独立的模块、默认路径/选项、几何或数据转换 | 不在接口未冻结时自行改公共数据结构 |
| V：验证与反例 | 独立断言、参考采集/负例、必要测试工具和反向审查 | 不通过放宽断言/删字段/改golden使实现通过 |

A/B/V是职责槽位，不是固定专业名称。E01分别为来源与许可、默认路径、断言清单；后续按下表切换。
每个任务必须写入本轮brief：任务ID、目标、输入、基线、独占可写路径、只读路径、依赖、交付格式和验收方式。
根agent在任务发出前创建brief；子agent先阅读brief和适用AGENTS，再执行。实例见 [E02 brief](iterations/E02.md) 和 [E03 brief](iterations/E03.md)。

## 3. 文件与接口归属

默认共享工作区，以文件级独占写权限隔离。一个文件任一时刻只有一个owner；读取其他lane产物可以，改动须先向根agent提出具体变更请求。
根agent独占AGENTS、README、全局计划/状态、UPSTREAM、兼容账本、公共check/CI入口和迭代汇总文件。子agent不更新全局完成状态。
子agent只创建获分配的文件和独立输出目录；实际代码未完成前不修改生产支持清单。不回滚、覆盖或清理不属于自己的改动。
公共模型、函数签名、profile schema和跨模块行为由根agent先冻结。生产代码尚依赖未定接口时，先交付来源/反例/实现草案，接口确定后再写入正式模块。
修改必需的共享文件时暂停该文件的其他写入，根agent明确转交owner或统一集成补丁；不采用“最后写入者覆盖”的方式解决冲突。
若同文件重构无法拆分，根agent可分配隔离worktree，并明确合并顺序；默认E01不需要worktree。
Git提交、分支操作、合并、推送和发布统一由根agent按已授权任务处理；子agent不自行执行这些操作。

## 4. 分波执行与测试屏障

v1.8补充：开发阶段先preflight与affected检查，公共入口在模块稳定后立即接入，root不用等待所有lane结束才集成。最终三平台full及真实安装门禁不变。只读来源数据按单次作用域复用、负控副本按完整依赖复制；不缓存PASS或缺失前提。完成记录变化可由严格的输入/命令/环境指纹与专属元数据校验收口，任何代码/测试/配置变化退回全量。请求只在相同候选与执行身份的一次run内复用，逐suite断言与独立重复不减少。性能结论必须基于无竞争的实际前后计时，不能用理论次数或同时跑两个重负载造成的基线变慢宣称提速。

1. **准备波**：根agent读取状态、保存起点、写brief/接口和所有权表，运行本轮所需基线检查。
2. **并行波**：A/B/V各自交付独立文件，运行自己所需的局部验证；根agent可并行处理集成设计、公共检查器或文档。
3. **交接波**：子agent提交handoff，保持自己文件稳定。根agent核对路径、SHA、结论与原始输出，安排另一lane只读反审。
4. **集成波**：处理差异/依赖，必要时给原owner发有边界的返工任务；接口或共同来源变动后重跑受影响验证。
5. **验收波**：所有写入暂停，根agent运行完整相关检查与来源/参考校验；固定被验文件SHA。不能在文件仍被修改时宣称集成检查已通过。
6. **复盘波**：写实际结果、协作问题和改进，应用当前可做的修正，更新下一轮brief/分工，再更新机器进度。

独立测试进程可并行，但使用不同的新输出目录，不能共同写一个capture、index、fixture或临时包。
全局check与reference capture会记录多文件SHA，须在稳定屏障内运行；子agent局部测试不得冒充最终集成验收。
共享测试目录中，lane局部unittest必须用`-p`限定自己拥有的测试文件；不能在其他lane产物未交付时运行全目录discover。全目录discover由root在稳定屏障执行。
若局部测试意外读到另一lane未完成的文件，保留原始失败，改为限定owner范围后重验；不修改对方文件或放宽测试来绕过。
独立检查逐命令捕获argv/cwd/stdout/stderr/退出码；不得将多个检查串联后只采最后一个shell退出码。若历史步骤只保留工具摘录，明确它不是原始日志字节，不重构为“原始stderr”。
接口变化、来源漂移或回归失败只使相关依赖等待，其他独立调查/反例工作继续。不可解释的结果不得通过删断言或扩大容差处理。

## 5. 沟通与交接格式

子agent发现会影响其他lane的默认值、接口、来源或失败时立即发简短消息给根agent，说明证据路径及受影响任务；跨lane协作先告知根agent。
不通过外部聊天/邮件发送项目消息；使用本轮agent协作通道。
长任务在关键发现、阻碍、接口需求或完成时报告；根agent向用户持续报告实际进展，不用无结论轮询替代工作。
handoff保存为机器可读JSON，至少包含：

```json
{
  "iteration": "E01",
  "taskId": "E01-A",
  "baselineCommit": "actual commit SHA",
  "status": "ready_for_review",
  "ownedPaths": [],
  "changedFiles": [{"path": "relative path", "sha256": "actual file SHA"}],
  "findings": [{"claim": "what was established", "evidence": [], "certainty": "verified|inferred|unresolved"}],
  "commands": [{"argv": [], "cwd": "actual cwd", "exitCode": 0, "logPath": "saved log"}],
  "unresolved": [],
  "reviewRequests": [],
  "nextAction": "concrete next action"
}
```

示例仅定义格式，任务必须填写真实数据；命令未执行时不填成功退出码。交接目录为`test-runs/<run>/<lane>/`，新建不覆盖。
需要持久化的来源/断言/阶段映射写入获分配的references文件；run内原始证据与版本化索引分开。
证据区分静态定位、推断、发行物实测和Python实现通过。含原始引用时记录commit/path/symbol/行范围/SHA；生成代码与原始Java身份分别陈述。

## 7. 每轮复盘与持续改进

每轮结束前写`docs/retrospectives/<iteration>.md`，记录真实任务/交付/验收、并行过程、冲突/返工/等待、未解决项与下一步。
至少比较“计划并行的工作”与“实际并行的工作”，指出强依赖导致的串行环节；无计时数据时不编造提速倍数。
改进条目包含问题、原因、具体措施、owner、适用下一轮、验收方式、状态及证据。能在本轮修正的立即修正，其余写入下一轮brief。
改进分为协作规范/接口划分/测试证据/实现方法，不用一句“加强沟通”代替动作。
根agent更新机器索引的retrospective字段和下一轮安排；本轮功能退出条件与复盘均完成后才标complete。
complete要求其前置迭代已完成、所需gate已核实、每条证据真实存在且SHA匹配，复盘必须属于该轮并包含交付/并行/问题改进/下一轮。全局检查拒绝任意非空占位证据、借用其他文档作复盘及伪通过元数据。
来源门禁仍未通过时，审计轮可按其既定范围完成，gate维持unverified，并写明后续可继续/必须等待的任务。
下一轮开始先检查上轮改进落实情况。规范变更在本文件记录，避免每轮重新发明协作流程。

初始版本v1：明确3条独立lane、共享文件独占、稳定验收屏障、真实handoff与逐轮复盘。
E01过程中已应用改进：共享tests/audit的局部discover限定owner文件；保留一次提前全目录discover产生的集成失败，统一留到root稳定屏障验收。
E01过程中已应用改进：验证逐命令采集退出码，防止后续成功命令掩盖前一失败；缺原始日志的步骤标记证据限制。
v1.1（E01复盘后）：完成/gate状态绑定真实证据SHA与专属复盘；映射、source span、planned符号、请求/预期及topic_only关系均有反例守卫。下一轮沿用 [E02 brief](iterations/E02.md) 的分波/文件归属，先落实E01改进再执行。
v1.2（E02复盘后）：先冻结规则/接口，等最后采集器版本稳定再封存事实收据；修改采集器后重采并重封引用，不覆盖原记录。只移除明确工具诊断路径，用户同名字段始终保留。
